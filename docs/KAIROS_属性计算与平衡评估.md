# KAIROS 属性计算路径与数学平衡评估

> 范围：研发期 46 种牌、10 名钟主、两套预组。以当前 C# 实现为准，不改 AI，不用 AI 胜率倒推职业强度。本文和工具一起构成可重复的评估基线。
> 用户已明确不要求旧存档兼容；本轮不开发迁移，不主动删除存档。卡池重构先以候选配置对照，**尚未同步进可玩版本**。

## 1. 结论先行

问题不是简单的“快攻攻击力不够”：

1. **场面资源数量不同**：破晓星轨 12 张侍从，其中两张拦截者仅限响应，常规可部署只有10；烈阳琥珀20张，其中10守卫、6蓄力。30张牌库在抽样10张时，期望侍从数分别4与6.67，但这仍不是同时在场数。
2. **早期可部署稳定性不同**：以基础时值≤初始视界2且可常规部署为标准，分别8张与10张。先手5张全缺概率 `C(22,5)/C(30,5)=18.48%` 与 `C(20,5)/C(30,5)=10.88%`；后手6张为12.57%与6.53%。调度能改善，不能把“印有侍从类型”都算早期部署。
3. **鸣钟不是简单回合结束**：同一次支付可能完成抽牌、重整、蓄力和技能冷却。慢牌部署后跨钟即重整；迅捷的差异化仅存在于“没有跨新钟仍有机会攻击”的窗口。不能给所有迅捷固定加相同分数。
4. **守卫＋血量断点＋成长**：奥瑞斯让钟楼守卫从1/3变1/4、正午卫士从1/4变1/5；2伤/3伤回答效率下降。每活过一钟，蓄力又+1/+1；“+1生命”可能多挡整次攻击，而不是仅多承受一小点损失。
5. **晨技能容易失去收益**：伊琳旧晨鸣与迅捷预组重叠，又要求当节新入场、未攻击、疲惫；阿迅旧技能先付1再减1通常净省0刻，跨钟还会立即过期；疾风连奏若支付跨钟，临时增攻会在下一次行动前清除。
6. **必须保留条件优势，不追求各栏相同**：夜的信息、暮的回收、永的存活收益不能全部折算成一项战力。当前样本只能证明结构性压力，不能证明“所有钟主的实际胜率”。

在无伤满血、无技能/部署、双方活过相同钟数的配对截面里：原晨夜攻击原昼永，一击击杀占比21.67%，击杀且存活13.33%；反向61.67%、53.33%。这是按卡组份数加权的**侍从配对指标，不是对局胜率**；它忽略了守卫限制、抽到/打出时点、攻击费用和操作者策略，不能直接拿50%作平衡目标。

历史弱AI400局中的50胜/400仅作为旧试玩复现记录，已排除出数学工具和重构验收依据；未修改AI策略。

## 2. 从输入到胜负的完整主链

```text
牌库/钟主/规则配置/种子
  → 构筑合法性 → 随机先行/洗牌/5或6张起手/调度
  → 决策状态：时标、行动权、视界、场地、手牌、待响应、选择
  → 合法动作和目标筛选
  → 基础费用+修正→最低1刻→视界门槛
  → 宣言：锁费用/目标/契机/连拍；扣砂、耗竭、冷却、移出手牌
  → 对方一次抢拍窗口 → 响应先结算
  → 原行动再校验/效果与状态检查/死亡队列
  → 逐刻支付：伏笔 → 己方咏唱或回声 → 新鸣钟
  → 预言补抽/死亡 → 逆流 → 双方64时尽比较
  → 新的行动权与下一次循环
```

源码入口：`Assets/Kairos/Engine/Flow/LegalCommands.cs`、`Assets/Kairos/Engine/Flow/ActionPipeline.cs`、`Assets/Kairos/Engine/Effects/EffectRunner.cs`、`Assets/Kairos/Engine/Timeline/TimelineService.cs`。基础配置实际位于 `Assets/Kairos/Engine/Data/CardDatabase.cs`，旧规格中的目录图不是当前物理路径。

### 2.3 费用与攻击的精确路径

对打牌/攻击/时器：

```text
c = 牌.time+实例CostDelta / 侍从cadence / 时器cost
c += 对方费用光环
若打牌：应用所有满足MinBaseTime的下一张牌状态
c += 命中预言的1刻
若抢拍：c += 免税?0:1
若连拍且当节减费未用：应用先手之律一次
若打牌：c -= 时砂（宣言扣除，即使过量）
最终 = max(1,c)
```

当前静候/蓄势/盖放在 `Cost` 提前返回，**不吃后面的光环/预言/先手之律/砂修正**。文案“下一行动+1”与这三个动作的当前执行存在边界差异，应在正式重构时补规格一致性测试，而不是数学工具悄悄更改。

- 静候费用=`max(1,min(64,对方时标+1)-自己时标)`；无视视界；不是免费过牌。
- 同时战斗：宣言时疲惫，结算时取攻击者当下攻击力；先记录对方非负反击值，再分别造成伤害，随后死亡检查。反击者疲惫/停滞也反击。
- 无盾一击击杀：`A≥H_enemy`；自身存活：`H>A_enemy`。有盾首击不杀；简化单向击杀次数=`ceil(H/A)+盾数`，但此式不包含反击/治疗/新盾/成长。
- `+1攻`只有跨过敌HP阈值才改变一击击杀；`+1血`只有跨过反击阈值才改变存活。CSV同时列出这些断点。
- 伤害/治疗/状态效果最终以引擎为准，工具不把伤害、卡差、时刻、信息强行兑换。

### 2.4 全部效果操作的计算方向

`effects.csv` 将全部85个显式/自动节点逐项列出，包含IF两分支、被动、光环、三个自动蓄力。新增未知op/关键字段会报错，不能静默当0强度。

|操作|原生计量与主要折损|
|---|---|
|DAMAGE / DAMAGE_ALL|命中目标各受amount；盾→0；过量伤害、是否即时/咏唱、能否打脸|
|HEAL / PAY_LIFE|回复夹上限 / 直接失去命烛；不要把支付当负伤害走盾|
|BUFF / BUFF_ALL / GROW_ALL|Atk/Hp/MaxHp变动，持续时间；Growth重复次数仅对蓄力目标|
|DESTROY / DESTROY_ALL / SACRIFICE|置HP0，忽略盾；牺牲记录原始时值供取砂|
|DRAW|逐张抽，满手焚毁、空库疲劳|
|SCRY / PICK_FROM_TOP|前N张信息/排列或选1进手；其余按规则置顶/底；非额外N张手牌|
|SUMMON_FROM_PAST|符合原始时值的往昔侍从，须有场位；疲惫、不触发部署；仍触发友方入场|
|REFRESH / STASIS / STASIS_ALL|增加/减少攻击机会窗口；不是直接伤害，仍受行动权/节奏/目标限制|
|SHIELD|未来一包正数伤害的防止值；毁灭和负HP的防止值0|
|GAIN_SAND / NEXT_CARD_COST|受上限/最低费用/有效目标/过期窗口影响；净省时间还需扣时器自身支付|
|PUSH_MARKER|按推迟上限逐刻走，可能帮敌人鸣钟；不是等量伤害|
|PUSH_OBJECT / PUSH_ALL_OBJECTS|物件位置+amount，锁定目标不变；推到64外可能令结算无法发生|
|PROPHECY|正确预测的条件卡差和费用差；类别与下一行动受双方策略影响，不套均匀25%|
|COUNTER_DECLARED|原牌无效进牌库底，仍付费用；反制不是永久移除卡牌|
|REDIRECT_ATTACK|原攻击改目标，反击按新目标；该效果来自拦截者自身ID|
|COPY_LAST_PLAYED|公开最后出牌的实例复制，可能有CostDelta；未出过牌/满手/昂贵复制降低收益|
|IF|严格分支；`E=p·V_then+(1-p)·V_else`仅在p是明确假设/观测值时成立|

当前回声对 `amount` 做整数除2，**不是所有字段都除2**；`atk/hp/count`不走相同缩放。现有46牌没有echo配置，增加回声卡必须先补实现语义与测试。

### 2.5 胜负检查

1. 命烛≤0即输；同一状态检查双方≤0为平；死亡先于侍从余音可能改变“能不能靠余音救命”。
2. 状态检查清侍从死亡，进入往昔、发余音/友军死亡/任意死亡事件。
3. 行动检查点处理预言抽牌，再死亡，再逆流。
4. 双方到64：先比命烛，再比场上非负攻击总和，再比手牌张数，仍相同则平。
5. 因此控场、过牌、生命均可能成为终局目标；不能只统计累计打脸伤害。

## 3. 数学模型：可证明什么、不能证明什么

### 3.1 抽样与调度

总数N、目标份数K、不放回抽n张：

`P(X=x)=C(K,x)C(N-K,n-x)/C(N,n)`；`E[X]=nK/N`。

本项目调度把丢弃牌先放回牌库再洗，因此可能重新抽到同一张。工具提供“保留所有目标牌，换掉所有非目标牌”的精确两段计算：先抽到j张目标，剩余总体N-j、目标K-j，再抽n-j张。**这是特定策略，不是AI推荐，也不是最优起手。**

抽8/10/12张表示“已抽样张数”，不是第8/10/12刻、不是手中仍有这些牌。过牌、鸣钟、焚毁与预见必须另建情景。

### 3.2 时间与生存

- `time.csv` 枚举起点0…15、可付费用、对手领先差0…8，记录是否仅支付后仍行动/新鸣钟/契机/减1刻后的变化。
- `deployment.csv` 枚举普通侍从部署起点，检查支付跨钟是否立即就绪/成长；不含响应、抢拍专用侍从、召回。
- 不用 `攻击/费用` 一项替代侍从价值：部署time和重复攻击cadence是不同投入，还受每4刻刷新限制。
- Growth条件存活n钟：`A(n)=A0+n,H(n)=H0+n`。假设每钟独立存活率s，活体攻击期望=`s^n(A0+n)`，只是压力测试；s必须随环境重新标定，不是常数真理。
- 例如苔藓守望者三钟后4/6是**存活者**属性；s=.5时场上期望攻击只有.5，而不是所有场景都免费得到4攻。

### 3.3 技能与被动，不做伪精确总分

`keepers.csv` 给冷却机会的上界与可用率25/50/75%扫描。窗口默认含0与16刻，CD1理论最多5次、CD2最多3次、CD3最多2次；实际可能没有目标/没有行动权/不值得使用，**不是实际使用次数**。

`keeper_scenarios.csv` 逐名给原生输出与输入假设，`effects.csv` 保留完整逻辑。每名钟主的审核重点：

|钟主|应测原生量|当前风险/本轮处置|
|---|---|---|
|伊琳|每小节免税实际省刻；合格疲惫目标与能兑现的额外攻击机会|候选晨鸣扩大至≤3费疲惫非停滞侍从，CD2；避免与迅捷重叠，限制高费大体型|
|阿迅|3连宣言的真实频率、保留抽牌；技能净省刻|候选减费2，先付1后对3费牌最多净省1；过期仍可能负收益|

### 局部概率建议：只随机额外信息，不随机基础可靠性

第一试验采用：齿轮学徒固定预见1，50%额外看1。不会把其基础体型、攻击命中、伤害、费用、守卫或鸣钟变成骰子。

- 可看张数 `X=1+Bernoulli(.5)`：均值1.5、方差.25。
- 剩余25张、8张目标时：固定看1找到目标32%；混合43.33%；固定看2为54.67%。这不是新增手牌，更不是多11.33%胜率。
- 观星学徒仍固定看2，保持夜学派信息稳定性；中立只获可控波动。
- 本轮工具支持任意p的数学比较，**引擎尚无概率op，卡牌候选不伪装成已支持字段**；要实装必须新增带种子分支、明确消耗RNG时点、公开日志、两结果/UI/重放测试。
- 不用随机爆伤/闪避/随机守卫绕过弥补结构差距。先修确定性结构，再测试少量信息随机是否真的改善选择。

## 5. 日后新增卡牌/牌组的评估门槛

1. 写明角色：早期场面、解场、过牌、节奏、成长或终结。至少说明一个弱点/反制窗口，稀有度不作为无条件超模理由。
2. 在相同model下生成基线/候选；保留版本、输入hash、改动理由。先只改变一类变量，最后才测试组合包。
3. 验证30张/份数/学派/钟主；新关键字/效果不能静默归0，要补路径、情景和测试。
4. 比较早期空窗、10张抽样场面量、2/3/4伤断点、1/3/5钟成长、护盾/无盾两种交换、减费跨钟与技能失效窗口。
5. 分别测试最低/基准/最高触发率、场上0/1/3/5侍从、手牌0/7/8、牌库0/1/N、目标已离场、64前、生命≤10。工具现成表不覆盖的状态交给引擎用例，不做无依据外推。
6. 统计告警不是自动通过：例如起手空窗显著上升、解牌主要阈值全跨不过、某防守组合没有可回答窗口、静候/低费动作收益无上限→必须给出设计解释或调整。
7. 最后才双人交叉试玩：同人交换牌组和先后手，记录技能可用却未用原因、死亡/关键牌时间、失去主动权、卡住回合、是否存在可理解反制。现阶段AI策略另做，不能拿弱AI当法官。
8. 若未来报告人类胜率，注明场数、玩家/配方/先后手分层、置信区间；避免重复同种子/同操作者样本当独立对局。
